# Interface languages

The interface speaks **English** (the default) and **Russian**. Notes are not translated;
they are the user's text.

Code: the engine is `packages/i18n` (`createTranslator(dictionary, locale)`, plurals,
`fill`, `richText`, `detectLocale`), shared by the app and the account site. A translator
holds its own language, so the site's server can render pages in several languages at once.
The app keeps a thin module-level wrapper and its dictionaries in
`apps/web/src/presentation/i18n/`; the site has its own in `apps/site/app/i18n/`.

- **Choice:** the setting "Language" (Settings; default "System"). For "System",
  `detectLocale` takes the first of the system's preferred languages (`navigator.languages`)
  that the app speaks, by base language (`ru-RU` → Russian), and falls back to English.
  `applyLanguage` in `i18n/setup.ts` sets the language and `<html lang>`. `main.tsx` imports
  `setup.ts` first, so the system's language is set before any other module runs, then applies
  the saved setting before the first render. Changing the setting switches the language at
  once: `App` renders its routes again, keyed by the language
  ([settings](settings.md#how-they-apply)).
- **Messages:** `en.ts` is the source of the keys (`"sidebar.tags": "Tags"`). `ru.ts` is typed
  as `Dictionary`, so a missing or extra key fails the type check; a test also checks that
  every translation keeps the same `{placeholders}`.
- **Use:** `t(key, params)` for text, `tn(key, count)` for plurals (forms chosen by
  `Intl.PluralRules`: one/other in English, one/few/many/other in Russian; `{count}` is the
  number formatted for the language), `rich(key, parts)` for messages with elements inside
  (links, code). Labels are looked up when rendering, never when a module loads: tables of
  labels (shortcuts, toolbar tools, settings options) hold keys.
- **Terminology:** the interface calls a note a **conspect** (plural "conspects"; in Russian
  «конспект», masculine, «конспекты»). Code, storage, the server API, URLs (`/notes/…`),
  message keys (`note.*`) and these docs keep "note". The tag tree is "Tags" / «Теги».
- **Dates** use `Intl` with the system's locale, whatever the interface language; numbers in
  messages use the interface language.
- **Not translated:** error details that come from outside the UI (exceptions from storage,
  the network, the YAML parser), and the welcome note's Markdown only when created (it is
  created in the interface language and is then an ordinary note).

## The account site

The site (`apps/site`) speaks the same two languages with its own dictionaries (`en.ts` the
source of keys, `ru.ts` typed as `Dictionary`, the same placeholder test). The language comes
from the `lang` cookie (the switch in the top bar), then the browser's `Accept-Language`,
then English, and is rendered into `<html lang>` on the server. Emails the server sends are
in the language the page asked for (`internal/mail/texts.go`), and the providers offered at
sign-in depend on it (Google, LinkedIn and X in English; Yandex ID and VK ID in Russian).

## Adding a language

To add a language to the app: add it to `LOCALES` and `LOCALE_NAMES`, write a `Dictionary` for it,
register it in `i18n.ts`, and add it to `Language` in `domain/settings/settings.ts` (and to
`parseSettings`).
